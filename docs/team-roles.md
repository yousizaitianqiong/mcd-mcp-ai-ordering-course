## 2. 真实下单复核规则

真实 create-order 具有外部副作用，固定采用以下责任分离：

1. 成员 D 负责准备运行环境、检查测试账号/地址和保存脱敏证据。
2. 成员 B 负责确认 Provider 参数、工具白名单和下游响应含义。
3. 一名操作成员在页面点击一次确认；另一名成员现场复核地址、商品、金额和报价有效期。
4. 不自动支付；下游返回未知状态时停止，不重试写操作。
5. 真实 Token、模型 Key、个人地址和支付信息不进入 GitHub Issue、Pull Request、截图或报告正文。

如果凭据、测试账号、配送地址或网络条件缺失，成员 D 将状态记为阻塞，成员 A 在最终报告中记录解除条件。

## 3. 建议排期

### 第 1 周：冻结需求和最小 Mock 闭环

- A 完成需求编号、用户故事、验收标准和报告目录。
- B 确认 FoodOrderProvider、ModelAdapter、MCP 客户端和确认闸门边界。
- C 完成页面布局、聊天输入、工具轨迹和 Mock 数据展示。
- D 完成 Mock 菜单、报价、订单状态和手工验收清单。

### 第 2 周：完成文档与本地联调

- A 完成架构接口、GitHub 调研矩阵、演示脚本和迭代记录。
- B 接入在线模型和查询类工具白名单，核对错误转换。
- C 接通 SSE、菜单/购物车/确认卡片。
- D 执行 Mock 全流程，记录构建结果和当前自动化测试数量。

### 第 3 周：真实 MCP 只读预检

- B、D 在受控环境验证 MCP 初始化、工具列表、地址、门店、菜单、优惠券和核价。
- C 核对真实结构化数据在页面上的展示。
- A 记录每项真实结果、响应时间、错误码和脱敏证据。
- 任一凭据或服务条件缺失时保留阻塞状态，不用 Mock 结果覆盖。

### 第 4 周：一次真实待支付下单与课程交付

- 两名成员复核真实地址、商品、金额、报价有效期和外部副作用。
- 只由操作成员点击一次真实确认，获取待支付订单号；不自动支付。
- D 记录订单状态和数据清理结果，未知状态不重试。
- A 完成最终报告、迭代记录和课堂演示材料。

排期可因外部账号和服务条件顺延；顺延时更新迭代记录，不伪造“已完成”。

## 4. 协作与合并规则

- 每项工作先建立或认领 Issue，在 Issue 或 Pull Request 中写目标、负责人和验收条件。
- 后端接口变化先更新架构文档，前端不依赖 Provider 私有字段。
- 合并前运行 pnpm test 和 pnpm build；同时记录 pnpm test 实际发现的测试数量。
- 文档分支使用 docs/主题；功能分支使用 feat/功能名；修复分支使用 fix/问题名。
- create-order 相关改动必须由两名成员复核，并在测试记录中注明是否触发外部副作用。
- 不提交 .env、MCP Token、模型 API Key、Authorization Header、真实手机号、个人地址、支付链接或未脱敏 MCP 响应。
