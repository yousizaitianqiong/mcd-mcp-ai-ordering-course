# 测试计划与验收记录

## 自动化测试

后端测试命令：

```powershell
pnpm test
```

计划覆盖：

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| T-001 | Mock 地址、门店、菜单查询 | 返回统一领域类型，模式为 Mock |
| T-002 | Mock 购物车和核价 | 商品价、配送费、优惠、总价一致 |
| T-003 | 报价确认 | 仅确认 API 调用 `createOrder`，生成待支付订单 |
| T-004 | 重复确认 | 第二次返回 `APPROVAL_ALREADY_USED`，不再次创建订单 |
| T-005 | 报价过期 | 返回 `QUOTE_EXPIRED`，不调用 `createOrder` |
| T-006 | MCP JSON/SSE 结构解析 | 正确提取 JSON-RPC result 和 SSE data |
| T-007 | MCP 401 / 429 / 超时 | 转换为可识别错误，不泄露 Authorization |
| T-008 | Tool 参数错误 | 不允许未知工具、空订单号或不在购物车的商品 |

## 真实 MCP 联调清单

在 `.env` 配置后按以下顺序执行：

1. `GET /api/health` 确认 `mode=mcd`，响应不包含 Token。
2. 查询地址和可配送门店。
3. 查询菜单、详情、优惠券。
4. 核价并记录原始报价与前端展示金额是否一致。
5. 只在测试人员人工确认后调用一次 `create-order`。
6. 查询 `query-order`，记录订单状态。
7. 清除或保护所有包含个人信息的本地数据。

## 当前实现的验证边界

Mock 路径应作为每次提交的必测路径。真实 MCP 和在线模型需要有效的外部凭据、网络和服务端账号，本仓库不内置这些条件；未完成真实联调时，在报告中明确写“接口适配已实现，真实服务联调待凭据和测试账号”。
