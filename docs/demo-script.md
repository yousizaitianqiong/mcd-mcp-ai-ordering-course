# 课堂演示脚本

建议先用默认 Mock 模式完整走一遍，再根据账号和网络情况决定是否展示官方 MCP 查询。整段演示控制在 6–10 分钟。

## 1. 介绍问题（约 1 分钟）

说明用户需要把“想吃什么”转换成地址、门店、菜单、价格和订单状态，但模型不能猜价格，也不能未经确认直接下单。本项目用 Provider 把外部餐饮服务和页面解耦。

## 2. 展示模式和安全边界（约 1 分钟）

1. 打开首页，指出顶部的“Mock 演示模式”标识。
2. 展示 `GET /api/health` 不返回 Token。
3. 说明 Token 只存在后端 `.env`，浏览器只收到结构化餐品和订单信息。

## 3. 自然语言查菜单（约 1 分钟）

在聊天框输入：

```text
我想吃麦香鸡套餐，先帮我看看当前菜单和门店
```

指出左侧工具调用轨迹，以及右侧地址、门店、菜单卡片。强调模型/规则代理先完成查询，没有执行创建订单。

## 4. 加购和核价（约 1 分钟）

点击“麦香鸡套餐”的“加入”，再点击“开始核价”，或输入“请核价当前购物车”。指出报价中的商品价、配送费、优惠、总价和有效期。

## 5. 人工确认闸门（约 1 分钟）

在核价卡片上核对地址、门店、商品和金额，然后点击“确认并创建待支付订单”。说明：

- `create-order` 不在模型工具列表中；
- 只有这个按钮调用 `/api/orders/confirm`；
- 服务端再次校验报价归属和有效期；
- 页面只展示待支付链接，不自动支付。

## 6. 订单状态（约 1 分钟）

展示订单号、状态和模拟支付链接，点击“刷新”。输入“查询订单状态”也可以复用当前会话查询最近订单。说明真实模式下状态由 `query-order` 返回，Mock 模式会明确标注为模拟状态。

## 7. 异常和回退（约 1 分钟）

说明项目覆盖 401、429、超时、空地址、无门店、商品失效、报价过期和重复确认；官方 MCP 不可用时不伪装真实结果，而是回到显式 Mock 模式，保证课程演示可复现。

## 可选真实 MCP 片段

如果已经准备好测试 Token，只展示地址、门店、菜单和核价。真实 `create-order` 必须先确认测试账号、配送地址、外部副作用和人工审批人；没有明确授权时只停留在核价页面。
