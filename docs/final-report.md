# AI 麦乐送助手课程项目最终报告结构

> 本文是最终报告模板，不是完成结果。每一节填写时必须引用可复核证据，并区分“已验证、部分完成、待凭据、未实现”。

## 使用说明

### 状态词定义

| 状态 | 使用条件 |
| --- | --- |
| 已验证 | 已有命令输出、脱敏请求/响应、页面截图或录屏等证据 |
| 部分完成 | 只有部分路径或部分字段通过，剩余内容已明确列出 |
| 待凭据 | 代码或文档路径已准备，但缺少 Token、测试账号、地址或网络 |
| 未实现 | 当前代码和文档均没有交付，不能用计划代替结果 |

### 填写规则

- 不把规划中的测试、演示或联调写成已完成。
- 真实 MCP 结果与 Mock 结果分开记录。
- 真实待支付下单必须写明操作时间、脱敏订单标识、状态和是否发生支付；不记录支付凭据。
- 所有截图、日志和请求摘要先脱敏，再放入报告或附件。
- 成员贡献按实际提交、审查、文档和演示证据描述，不平均分配未经验证的工作。

### 6.3 真实 MCP

真实联调必须单独填写：

- 测试环境和协议版本。
- 地址、门店、菜单、优惠券和核价是否真实返回。
- 在线模型是否完成查询类工具调用。
- 操作成员和复核成员。
- 一次真实 create-order 的时间、脱敏订单标识和待支付状态。
- 是否发生任何支付；本项目预期为未支付。
- 401、429、超时、商品失效或报价过期等失败情况。
- 凭据和本地个人数据的清理结果。

如果缺少 Token、测试账号、配送地址或网络，状态必须写“待凭据/阻塞”，不能用 Mock 证据替换。

## 8. 风险、限制和未完成事项

至少覆盖：

- 真实 MCP 凭据、测试账号和网络依赖。
- 真实 create-order 的外部副作用。
- 当前无自动化测试。
- 课程版本没有登录鉴权和生产级持久化。
- 远程工具字段变化、协议版本变化和下游限流。
- 未完成的 query-order 真实状态验证、支付和履约能力。

每项风险写负责人、影响、缓解措施和下一步，不用“已解决”替代证据。

## 9. 项目总结与后续计划

从问题解决过程总结：

- 需求如何从自然语言转成接口和状态。
- Provider 抽象、Mock 回退和人工确认闸门带来的价值。
- 小组协作中哪些接口和证据最有帮助。
- 下一阶段应优先补自动化测试、并发幂等、鉴权还是生产级存储，并说明选择依据。
