# 测试计划与验收记录

> 本文定义验证方法和证据格式。当前仓库没有自动化测试文件；pnpm test 的成功退出码只表示测试运行器没有失败，不能表述为已有测试全部通过。

## 1. 验证层级

| 层级 | 目标 | 必须证据 | 当前口径 |
| --- | --- | --- | --- |
| 静态/构建 | 确认 TypeScript 和前端生产构建可完成 | pnpm build 输出 | 当前基线已验证，交付前复核 |
| 自动化 | 验证后端业务和错误分支 | pnpm test 输出及测试文件清单 | 当前为 0 个测试，不能虚报覆盖率 |

## 5. 真实 MCP 联调清单

### 5.1 只读预检

1. 在仓库外确认测试账号、配送地址、服务条款和人工操作人。
2. 只在服务端本地 .env 配置 APP_MODE=mcd、MCD_MCP_TOKEN 和在线模型变量。
3. 访问 /api/health，确认 mode=mcd、provider=mcd、modelConfigured=true，响应不含 Token。
4. 通过在线模型完成地址、门店、菜单、餐品详情和优惠券查询。
5. 发起真实核价，核对金额、地址、门店、商品和有效期。

### 5.2 受控真实下单

1. 操作成员和复核成员共同核对报价。
2. 只点击一次页面确认按钮，验证真实 create-order 返回外部订单号和待支付状态。
3. 不自动支付，不因未知状态或网络异常重试写操作。
4. 记录脱敏订单标识、时间、状态、错误码和是否产生外部副作用。
5. 清除或保护本地真实响应、地址和凭据。

## 6. 安全检查

- 浏览器 Network/Source 中无 MCP Token、模型 Key、Authorization Header 和支付信息。
- 服务端日志只保留脱敏事件、错误码和订单脱敏标识。
- data/app-state.json 只包含会话、报价、订单号和脱敏审计摘要。
- 截图和录屏遮盖真实地址、手机号、完整支付链接和凭据。
- 真实 create-order 只执行一次；失败或未知状态停止并升级人工判断。
